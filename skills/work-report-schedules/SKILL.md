# Work Report Schedules

用户明确要求创建/更新安排才执行。先定位同包 daily-report 的 scripts/report.py，运行 config 和 doctor，核对时区、DWS 与用户是否启用自动提交。读取本机自动化工具实际 schema，不直接写 automation.toml，不复制作者的 projectId、机器路径或模型配置。

默认配置：工作日 18:30 日报、每周一 18:00 周报，Asia/Shanghai；周报 previous_workweek 汇总上一完整周一到周五。配置改变时按用户要求更新，current_workweek 可用于周五本周总结，不混用两种周期。

## 定时提示词

日报：

> 调用 $daily-report，使用 --scheduled 解析配置时区的当日日报窗口，读取允许的 summaries、已完成 Codex 回合和同期钉钉工作文本。先完整预览三字段与来源覆盖，不读取原始会话、Git 或媒体。按实际配置处理提交/取消/修改：自动提交关闭时等待明确提交；开启时完整等待配置分钟数，并核查当前任务预览后的回复，再由确认心跳处理同一 run_key。任何缺口、身份或模板不明时只预览。不得重复提交，不显示个人路径或凭证。

周报：

> 调用 $weekly-report，使用 --scheduled 和实际 weekly_mode 解析统计周期，读取允许的 summaries、已完成 Codex 回合及同期钉钉日报。先预览四字段及覆盖，不读取原始会话或 Git。按配置处理提交/取消/修改；自动提交默认关闭，开启时只有完整等待且预览后无任何回复才允许自动提交。提交前检查状态、哈希、动态模板、登录身份和远端同周期报告。未知或失败时停下，不重试发送。

## 创建方式

优先按产品提供的当前任务 heartbeat 机制保存 recurring 安排；只有用户明确要求每次独立新任务或独立项目执行时用 cron。cron 前调用 list_projects，使用真实返回的 projectId，不能假定支持 null。模型与推理设置保留用户默认，不固化作者环境。

创建前只读检查已有同目的安排（包含旧名字），更新匹配项，存在多个无法消歧时询问用户。创建后核对状态、实际时间、时区、目标任务/项目和下一次运行；只在工具返回成功时报告安排成功，不展示内部 RRULE。

本 Skill 不自行提交钉钉日志，不默认开启超时提交，不修改已有个人版定时任务。DWS 或自动化工具不可用时说明并停下，不用系统 cron/launchd/计划任务绕过用户选择。项目级本地安排依赖电脑开机、桌面应用运行与项目存在；不要承诺关机后仍自动执行。
